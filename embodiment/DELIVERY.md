## Recovery and handoff

Use the existing branch/workflow for code changes when work begins. Asset rollback selects the previous package. Core persistence changes are additive, backed up via the core's existing mechanism; failed migrations leave the original database recoverable. Failed body startup leaves text available. A failed dispatched action with uncertain effect uses UNKNOWN and observation, rather than automatic repetition.

Each work-item file records requirements, scope, starting evidence, done criteria and recovery. Actual code paths and exact commands are filled by WRK-1000 from the checkout. They are deliberately not guessed from architecture document names.
